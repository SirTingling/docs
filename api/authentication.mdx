Every API request requires an API key in the `Authorization` header.

## Authenticating requests

Pass your API key as a Bearer token:

```bash
curl https://cloud.takumo.io/api/v1/rules \
  -H "Authorization: Bearer your-takumo-api-key"
```

In code:

```typescript
const response = await fetch("https://cloud.takumo.io/api/v1/rules", {
  headers: {
    "Authorization": `Bearer ${process.env.TAKUMO_API_KEY}`
  }
});
```

The gateway (`gateway.takumo.io/v1/messages`) takes the same `Authorization: Bearer` header. The OpenAI-compatible route (`/v1/chat/completions`) is temporarily unavailable. See [AI Tools](/ai-tools/overview).

<Warning>Connecting AI tools through the Takumo gateway with an API key is not available yet, on `gateway.takumo.io` or on a self-hosted gateway. Contact Takumo support at [support@takumo.io](mailto:support@takumo.io) for early access.</Warning>

## How keys are validated

1. Takumo receives your key from the `Authorization` header.
2. It computes a SHA-256 hash of the raw key.
3. The hash is looked up in the database.
4. If found and not revoked, the request proceeds.
5. Constant-time comparison prevents timing attacks.

The raw key is never stored. It exists only at creation time. After you close the creation dialog in the dashboard, the only copy is the one you saved.

## Key prefixes

An API key is 64 hex characters. The **API Keys** page labels each key with a prefix made from its first eight characters:

| Prefix | Environment |
|--------|-------------|
| `tk_` | Live |
| `tk_test_` | Test |

The prefix is a label, not part of the key. Send the key exactly as it was shown when you created it.

## Key scopes

Each key has a set of scopes. A request to a route that needs a scope the key doesn't have returns `403`. Scopes use colon notation:

| Scope | Routes that check it |
|-------|----------------------|
| `scan:read` | `GET /issues`, `/violations`, `/repositories`, `/compliance` |
| `audit:read` | `GET /audit-log` |
| `policies:write` | `POST /rules`, `PATCH` and `DELETE /rules/:ruleId`, `POST /rules/:ruleId/publish` |
| `reports:read` | `GET /reports`, `/reports/:id`, `/reports/schedules` |
| `reports:write` | `POST /reports/generate`, schedule create, update and delete |
| `notifications:write` | `POST /notifications/digest` |

Routes not listed need a valid key but no scope. Assign the minimum scopes needed. See [API Keys](/dashboard/api-keys) for how to set them.

## Rate limit headers

Gateway responses (`gateway.takumo.io`) include rate limit headers. The Cloud API does not send the `X-RateLimit-*` headers; on a `429` it sends `Retry-After`.

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests allowed in the current window |
| `X-RateLimit-Remaining` | Requests remaining in the current window |
| `X-RateLimit-Reset` | Unix timestamp when the window resets |
| `Retry-After` | Seconds to wait before retrying (only present on `429` responses) |

Example response headers:

```
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 42
X-RateLimit-Reset: 1710360000
```

When you receive a `429 Too Many Requests`, stop and wait for the number of seconds specified in `Retry-After`. See [Rate Limits](/api/rate-limits) for per-plan limits.

## Key rotation

For zero-downtime rotation:

1. Create a new key with the same scopes.
2. Deploy the new key to your tools.
3. Verify requests succeed with the new key.
4. Revoke the old key.

Revocation takes effect within seconds. A revoked key returns `401 unauthorized` immediately. There is no undo.

## Error responses

| Status | Code | When |
|--------|------|------|
| `401` | `unauthorized` | Missing key, invalid key, expired key, revoked key |
| `403` | `forbidden` | Key lacks required scope, feature not available on your plan |
| `429` | `rate_limited` | Too many requests in the current window |

See [Errors](/api/errors) for the full error response format.

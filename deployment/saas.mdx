The fastest path. Sign up, get an API key, point your tool at the gateway. No infrastructure to manage.

<Warning>Connecting AI tools through the Takumo gateway with an API key is not available yet, on `gateway.takumo.io` or on a self-hosted gateway. Contact Takumo support at [support@takumo.io](mailto:support@takumo.io) for early access.</Warning>

## Getting started

<Steps>
  <Step title="Sign up">
    Go to [cloud.takumo.io](https://cloud.takumo.io) and create an account.
  </Step>
  <Step title="Create an organization">
    After signing in, create a new organization. This is where your team, API keys, policies, and audit log live.
  </Step>
  <Step title="Create an API key">
    Navigate to **API Keys** and click **Create Key**. Give it a name that identifies where it will be used (for example `cursor-laptop`, `ci-pipeline`). Copy the key immediately. It is shown once.
  </Step>
  <Step title="Configure your AI tool">
    For Anthropic tools, set the API base URL in your AI tool to:
    ```
    https://gateway.takumo.io
    ```
    Send your Takumo API key as `Authorization: Bearer`, the only header the gateway reads it from. Use the auth token or bearer token setting rather than the API key setting where the tool has both, because some tools send the API key as `x-api-key`, which the gateway rejects with `401`. The gateway calls Anthropic with Takumo's provider key.

    For OpenAI-compatible tools, set the base URL to `https://gateway.takumo.io/v1` and enter your Takumo API key as the API key. These tools send it as `Authorization: Bearer`. The gateway calls OpenAI with Takumo's provider key, and an OpenAI key of your own is not used. See [AI Tools](/ai-tools/overview) for tool-specific instructions.
  </Step>
  <Step title="Set the API key">
    ```bash
    export TAKUMO_API_KEY="your-takumo-api-key"
    ```
    Or add it to your `.env` file:
    ```bash
    TAKUMO_API_KEY=your-takumo-api-key
    ```
  </Step>
  <Step title="Start coding">
    Secrets are now protected. Every request through the gateway is scanned, tokenized, and logged in the audit trail.
  </Step>
</Steps>

## Gateway URL

All requests go through a single endpoint:

```
https://gateway.takumo.io/v1
```

This URL replaces the AI provider's API base URL in your tool configuration. The gateway sends `/v1/chat/completions` requests to OpenAI and `/v1/messages` requests to Anthropic. Anthropic SDKs and Claude Code add `/v1/messages` themselves, so for them use `https://gateway.takumo.io` without `/v1`.

## What you get

| Capability | Details |
|-----------|---------|
| Secret detection | All [supported patterns](/patterns/supported) are active by default |
| Audit log | Every request is logged with detection results |
| Rate limiting | Per-organization limits based on your [plan](/reference/plan-comparison) |
| Policy enforcement | Configure custom rules in the dashboard |
| Zero infrastructure | Takumo manages the gateway, coordinator, database, and monitoring |

## Verifying it works

Check that the gateway is reachable and that your key is valid:

```bash
curl https://gateway.takumo.io/health
# {"status":"ready"}

curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $TAKUMO_API_KEY" \
  https://cloud.takumo.io/api/v1/rules
# 200 means the key is valid; 401 means it is missing, wrong or revoked
```

Then send a prompt that contains a fake secret (for example `AKIAIOSFODNN7EXAMPLE`) from your AI tool, and check the **Audit Log** in the dashboard to confirm the event was recorded.

<Tip>SaaS is the right choice for most teams. You get the same protection without managing infrastructure. On-prem is for organizations with strict data residency requirements.</Tip>

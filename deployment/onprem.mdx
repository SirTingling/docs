For organizations that need full control over where their data flows. Deploy the gateway and coordinator in your Kubernetes cluster.

## Prerequisites

| Requirement | Minimum Version |
|------------|----------------|
| Kubernetes | 1.27+ |
| Helm | 3.x |
| PostgreSQL | 15+ (or Neon Postgres) |
| Redis | 7+ |
| Container registry access | Outbound HTTPS to `cr.takumo.io` (Takumo's authenticated container registry, per-tenant deploy token) |

## Deployment

<Steps>
  <Step title="Add the Helm repository">
    ```bash
    helm repo add takumo https://charts.takumo.io
    helm repo update
    ```
  </Step>

  <Step title="Create namespace and secrets">
    ```bash
    kubectl create namespace takumo
    ```

    Create the database credentials for the coordinator:

    ```bash
    kubectl create secret generic coordinator-database \
      --namespace takumo \
      --from-literal=database-url="postgres://user:pass@host:5432/takumo" \
      --from-literal=database-url-direct="postgres://user:pass@host:5432/takumo"
    ```

    Create the JWT signing and verification keys for the coordinator:

    ```bash
    kubectl create secret generic coordinator-jwt-signing \
      --namespace takumo \
      --from-file=signing.pem=./signing.pem \
      --from-file=verification.pem=./verification.pem
    ```

    Create the JWT public key for the gateway (this is the same `verification.pem` file, stored under the key `public.pem`):

    ```bash
    kubectl create secret generic aegis-jwt-key \
      --namespace takumo \
      --from-file=public.pem=./verification.pem
    ```

    Create the image pull Secret for `cr.takumo.io`. Issue a deploy token
    in the Takumo dashboard (Settings, Deploy Tokens); the dialog shows your
    workspace ID beside it. The token is read without echo, so it stays out
    of shell history, the screen and process arguments. Full reference:
    [Deploy Tokens](/dashboard/deploy-tokens).

    ```bash
    read -rs TAKUMO_DEPLOY_TOKEN
    printf '{"auths":{"cr.takumo.io":{"username":"%s","password":"%s"}}}' "<workspace-id>" "$TAKUMO_DEPLOY_TOKEN" \
      | kubectl create secret generic takumo-pull-secret -n takumo \
          --type=kubernetes.io/dockerconfigjson --from-file=.dockerconfigjson=/dev/stdin
    unset TAKUMO_DEPLOY_TOKEN
    ```

    The charts check at install time that `takumo-pull-secret` exists in the
    namespace with type `kubernetes.io/dockerconfigjson`, and stop with these
    commands if it does not. Create the namespace first (as above) rather than
    passing `--create-namespace`.

    **Air-gapped:** if your cluster has no egress to `cr.takumo.io`, mirror
    the four service images (`aegis-shield`, `gateway-coordinator`,
    `sentinel-service`, `vault-service`) plus `mirror/redis` into your
    internal registry, override `image.repository` in your values file,
    and set `imagePull.existingSecret` to the Secret holding that registry's
    pull credentials.
  </Step>

  <Step title="Deploy the coordinator">
    The coordinator uses the `manual` secrets provider for on-prem, meaning it expects you to create Kubernetes secrets yourself (done in the previous step).

    Deploy initially with the join key disabled (you'll create it in a later step):

    ```bash
    helm install gateway-coordinator takumo/gateway-coordinator \
      --namespace takumo \
      --version 0.2.0 \
      --values https://charts.takumo.io/gateway-coordinator/0.2.0/values-onprem.yaml \
      --set secrets.joinKey.enabled=false
    ```

    This sets:
    - `secrets.provider: manual`
    - `secrets.database.enabled: true` with secret name `coordinator-database`
    - `secrets.jwtSigning.enabled: true` with secret name `coordinator-jwt-signing`

    <Note>The base chart defaults to `cloud-database` for the database secret name. The on-prem values overlay changes this to `coordinator-database` to match the secret created above.</Note>

    Verify the coordinator is running:

    ```bash
    kubectl get pods -n takumo -l app.kubernetes.io/name=gateway-coordinator
    ```
  </Step>

  <Step title="Deploy the gateway">
    ```bash
    helm install aegis-shield takumo/aegis-shield \
      --namespace takumo \
      --version 0.3.0 \
      --values https://charts.takumo.io/aegis-shield/0.3.0/values-onprem.yaml \
      --set connector.grpcUrl="gateway-coordinator.takumo.svc.cluster.local:9090"
    ```

    This configures the gateway to connect to the coordinator via gRPC on port 9090 and disables the cloud connector (`cloud.enabled: false`).

    Verify the gateway is running:

    ```bash
    kubectl get pods -n takumo -l app.kubernetes.io/name=aegis-shield
    ```
  </Step>

  <Step title="Create a join key in the dashboard">
    Go to **Settings > Gateway** in the dashboard and click **Create Join Key**. Give it a name (e.g., `production-cluster`). Copy the key immediately.
  </Step>

  <Step title="Configure the gateway and coordinator with the join key">
    Create the join key secrets for both the gateway and the coordinator:

    ```bash
    kubectl create secret generic aegis-join-key \
      --namespace takumo \
      --from-literal=join-key="your-join-key-here"

    kubectl create secret generic coordinator-join-key \
      --namespace takumo \
      --from-literal=join-key="your-join-key-here"
    ```

    Upgrade the gateway to use it:

    ```bash
    helm upgrade aegis-shield takumo/aegis-shield \
      --namespace takumo \
      --version 0.3.0 \
      --reset-then-reuse-values \
      --set secrets.joinKey.enabled=true \
      --set secrets.joinKey.secretName=aegis-join-key
    ```

    Upgrade the coordinator to use it:

    ```bash
    helm upgrade gateway-coordinator takumo/gateway-coordinator \
      --namespace takumo \
      --version 0.2.0 \
      --reset-then-reuse-values \
      --set secrets.joinKey.enabled=true
    ```

    Use `--reset-then-reuse-values`, not `--reuse-values`, for every upgrade.
    It applies the new chart's defaults and keeps the values you set yourself.
    `--reuse-values` replays the old chart's defaults instead, which can point
    pods at an old pull Secret name such as `ghcr-pull-secret`; the chart then
    stops the upgrade and names it.
  </Step>

  <Step title="Verify the connection">
    Check the **Fleet** page in the dashboard. Your gateway instance should appear with a **Connected** state.

    You can also verify locally:

    ```bash
    kubectl logs -n takumo -l app.kubernetes.io/name=aegis-shield --tail=20
    ```

    Look for a log line indicating successful registration with the coordinator.
  </Step>
</Steps>

<Warning>The join key is shown once. Store it in your secrets management system (Vault, AWS Secrets Manager, etc.) before closing the dialog.</Warning>

## GitOps installs (ArgoCD, Flux)

Create the namespace and the pull Secret (or a SealedSecret or External Secret that produces a
`kubernetes.io/dockerconfigjson` Secret) before the first sync, and set `imagePull.existingSecret` if you use
another name. Use `imagePull.existingSecret`, never `imagePull.deployToken`, in a repository.

ArgoCD renders charts with `helm template`, so the install-time check that the pull Secret exists does not run
there: a missing Secret shows up as `ImagePullBackOff` with a `401 Unauthorized` event, not as a failed sync, and
the chart's install notes are not shown. Flux's helm-controller runs the check, so a missing Secret fails the
HelmRelease with the same message as `helm install`.

If your installer cannot list Secrets in the namespace (for example Helm with `HELM_DRIVER=configmap` or `sql`
and RBAC without `list` on Secrets), set `imagePull.skipInstallCheck: true`.

## Required secrets reference

### Coordinator

| Secret Name | Keys | Description |
|------------|------|-------------|
| `coordinator-database` | `database-url`, `database-url-direct` | PostgreSQL connection strings (pooled and direct) |
| `coordinator-jwt-signing` | `signing.pem`, `verification.pem` | JWT signing and verification key pair |
| `coordinator-join-key` | `join-key` | Join key for gateway authentication (optional) |

### Gateway

| Secret Name | Keys | Description |
|------------|------|-------------|
| `aegis-jwt-key` | `public.pem` | JWT public key for auth verification |
| `aegis-join-key` | `join-key` | Join key for coordinator registration |
| `takumo-pull-secret` | `.dockerconfigjson` (type `kubernetes.io/dockerconfigjson`) | Image pull Secret for `cr.takumo.io`, from a deploy token in the Takumo dashboard. Rename with `imagePull.existingSecret`. All four charts use it. |

## Network requirements

The gateway needs outbound access to:

- Your AI provider (e.g., `api.anthropic.com`, `api.openai.com`)
- The coordinator gRPC endpoint (port 9090)

The coordinator needs:

- Access to PostgreSQL
- Inbound gRPC from gateway pods (port 9090)
- Inbound HTTP for health checks (port 8080)

Both services create NetworkPolicy resources by default (`networkPolicy.enabled: true`).

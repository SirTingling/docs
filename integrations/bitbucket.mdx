Connect Bitbucket to run Sentinel on pull requests and sync repository data. Takumo supports both Bitbucket Cloud and Bitbucket Server (Data Center).

---

## Setup

### Bitbucket Cloud

<Steps>
  <Step title="Enter your credentials">
    Go to **Dashboard > Integrations > Bitbucket** and click **Connect**. Enter your email, API token (App Password), and workspace name.
  </Step>
  <Step title="Select repositories">
    Takumo fetches repos from your workspace. Select which ones to track.
  </Step>
  <Step title="Add the webhook">
    Takumo does not register webhooks in Bitbucket. Add one yourself, as described in [Webhook setup](#webhook-setup).
  </Step>
</Steps>

### Bitbucket Server / Data Center

<Steps>
  <Step title="Enter server URL">
    Go to **Dashboard > Integrations > Bitbucket Server** and enter your instance URL.
  </Step>
  <Step title="Authenticate">
    Provide a username and App Password. The account needs read access to repos and write access to pull requests (for build statuses and comments).
  </Step>
  <Step title="Select projects">
    Takumo fetches all projects from your instance. Select which ones to track.
  </Step>
  <Step title="Add the webhook">
    Takumo does not register webhooks in Bitbucket. Add one yourself, as described in [Webhook setup](#webhook-setup).
  </Step>
</Steps>

## Webhook setup

Takumo checks a pull request only when Bitbucket signs the delivery with this integration's webhook secret. The secret decides which organization a delivery belongs to, so Takumo never guesses from the repository name.

<Steps>
  <Step title="Create a secret">
    Go to **Dashboard > Integrations**, find Bitbucket and click **Configure**. Copy the **Webhook URL**, then click **Create secret** and copy the secret. Takumo shows it once and can't show it again. An integration that was connected before this existed has a secret that was never shown, so click **Create new secret** to replace it.
  </Step>
  <Step title="Add the webhook in Bitbucket">
    In the repository, open **Repository settings**, then **Webhooks**, and add a webhook. Paste the URL and the secret. Choose the pull request created and updated events and repository push. On Server, choose opened, source branch updated and repository refs changed.
  </Step>
</Steps>

Takumo refuses a delivery it can't verify with `401`:

| Case | What Takumo does |
|------|------------------|
| The integration has no secret | Refuses every delivery. Create a secret first. |
| The signature is missing or wrong | Refuses the delivery |
| Two organizations connect the same repository name and the signature verifies for both | Refuses the delivery as ambiguous. Give each integration its own secret. |
| No organization has the repository | Ignores the delivery and answers `200`, so Bitbucket does not retry it |

Creating a new secret stops the current webhook until you update the secret in Bitbucket.

## What happens on a pull request

When a PR is created or updated:

1. Takumo sets a build status on the commit (`INPROGRESS`)
2. Custom policies are evaluated against changed files
3. Sentinel AI runs (if enabled)
4. Build status updates to `SUCCESSFUL` or `FAILED`
5. Takumo posts or updates a PR comment with findings

Build status key: `takumo-policy-check`. This appears in Bitbucket's merge checks if you've configured required build statuses.

## Repository sync

| Feature | Cloud | Server |
|---------|-------|--------|
| Branch restrictions | Yes | Yes |
| Required approvals | Yes | Yes |
| CODEOWNERS | Yes | No |
| Security scanning | No (native) | No (native) |

<Note>Bitbucket doesn't have native secret scanning, code scanning, or Dependabot equivalents. Takumo fills this gap with Sentinel scanning on PRs and the gateway's outbound protection.</Note>

---

## Periodic sync

In addition to webhooks, the Cloud Worker runs periodic Bitbucket sync jobs. This catches any webhook misses and keeps compliance data current.

---

## Webhook events

### Cloud

| Event | Action |
|-------|--------|
| `pullrequest:created` | Policy check + Sentinel review |
| `pullrequest:updated` | Policy check + Sentinel review |
| `repo:push` | Brain re-indexing + compliance sync |
| `issue:updated` | Ticket sync |

### Server

| Event | Action |
|-------|--------|
| `pr:opened` | Policy check + Sentinel review |
| `pr:from_ref_updated` | Policy check + Sentinel review |
| `repo:refs_changed` | Brain re-indexing + compliance sync |

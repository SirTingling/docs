# Installation

Takumo has two main components: the **CLI/API** for programmatic use and the **extension** for editor integration. Install whichever you need — or both.

---

## VS Code / Cursor Extension

The fastest way to get Takumo running. Install from your editor's marketplace.

<CodeGroup>

```bash VS Code
code --install-extension takumo.takumo
```

```bash Cursor
# Search "Takumo" in Cursor's extension panel
# Or download the universal VSIX from the VS Code Marketplace
```

</CodeGroup>

Or search **"Takumo"** in the Extensions panel (`Cmd+Shift+X`).

The daemon binary downloads automatically on first activation. No manual setup needed.

## CLI / API (npm)

For programmatic use, CI/CD pipelines, and custom integrations.

<Note>
The Aegis CLI is currently in early access. If `npm install` reports the package isn't found, email [support@takumo.io](mailto:support@takumo.io) for preview access.
</Note>

<CodeGroup>
```bash npm
npm install -g @takumo/aegis
```

```bash pnpm
pnpm add -g @takumo/aegis
```

```bash yarn
yarn global add @takumo/aegis
```
</CodeGroup>

This installs the `takumo-aegis` binary globally with both the CLI and the API.

## Gateway (on-premises)

For teams deploying Takumo in their own infrastructure. Images come from `cr.takumo.io`, Takumo's authenticated
container registry, and every pull needs a deploy token. Issue one in the dashboard under
[Settings, Deploy tokens](https://cloud.takumo.io/dashboard/settings/deploy-tokens); the dialog shows your
workspace ID beside it.

```bash
helm repo add takumo https://charts.takumo.io
helm repo update

# 1. Create the namespace, then the pull Secret. The token is read without echo,
#    so it stays out of shell history, the screen and process arguments.
kubectl create namespace takumo
read -rs TAKUMO_DEPLOY_TOKEN
printf '{"auths":{"cr.takumo.io":{"username":"%s","password":"%s"}}}' "<workspace-id>" "$TAKUMO_DEPLOY_TOKEN" \
  | kubectl create secret generic takumo-pull-secret -n takumo \
      --type=kubernetes.io/dockerconfigjson --from-file=.dockerconfigjson=/dev/stdin
unset TAKUMO_DEPLOY_TOKEN

# 2. Install. Pods use takumo-pull-secret by default.
helm install aegis-shield takumo/aegis-shield -n takumo
```

If `takumo-pull-secret` is missing from the namespace, or is not a `kubernetes.io/dockerconfigjson` Secret,
`helm install` stops before creating anything and prints the commands above. To use a Secret with another name,
pass `--set imagePull.existingSecret=<name>`. Create the namespace first rather than using `--create-namespace`:
the Secret has to exist before the install.

Outbound HTTPS to `cr.takumo.io` is the only network requirement for image access. Deploy tokens can be revoked at
any time; see [Deploy Tokens](/dashboard/deploy-tokens) for what revocation does and does not stop.

**Air-gapped environments:** mirror `cr.takumo.io/aegis-shield`, `cr.takumo.io/gateway-coordinator`,
`cr.takumo.io/sentinel-service`, `cr.takumo.io/vault-service` and `cr.takumo.io/mirror/redis` into your internal
registry, override `image.repository` (and `redis.image.repository` for Aegis Shield) in your values file, and set
`imagePull.existingSecret` to the Secret that holds your registry's pull credentials.

## Environment variables

| Variable | When needed | Description |
|----------|-------------|-------------|
| `ANTHROPIC_API_KEY` | `shield` command only | Your Claude API key |
| `TAKUMO_API_KEY` | Cloud features | Your Takumo API key |

The `scan` and `tokenize` commands work completely offline. Only `shield` needs an API key because it actually calls Claude.

## Verify it works

```bash
npx takumo-aegis --version
# takumo-aegis 0.1.0-alpha

npx takumo-aegis --help
# Usage: takumo-aegis <command> [options]
#
# Commands:
#   scan <path>       Find secrets in files
#   tokenize <file>   Show tokenized output
#   shield <file>     Full AI round-trip
```

## Requirements

- **CLI/API:** Node.js 20 or higher. macOS, Linux, or Windows (WSL recommended).
- **Extension:** VS Code 1.85+, Cursor, or any VS Code-compatible editor. macOS (Intel/Apple Silicon), Linux (x64/arm64), or Windows (x64).

<Accordion title="Node version issues?">
If you're on an older Node version:

```bash
# Using nvm
nvm install 20
nvm use 20

# Verify
node --version  # Should be v20.x.x or higher
```
</Accordion>

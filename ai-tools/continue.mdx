# Continue.dev

Continue is open source and lets you configure custom provider endpoints. Point it at your Takumo gateway and every request to an Anthropic model is protected.

<Warning>The OpenAI-compatible route (`/v1/chat/completions`) is temporarily unavailable. Don't configure OpenAI models in Continue to use the gateway yet. Anthropic models are not affected.</Warning>

## Setup

<Steps>
  <Step title="Get your API key">
    Log into [cloud.takumo.io](https://cloud.takumo.io) and copy your Takumo API key from the dashboard. For Claude models you also need your own Anthropic API key.
  </Step>
  <Step title="Open your Continue config">
    Continue stores its configuration at `~/.continue/config.json` (or `config.ts` if you prefer TypeScript).

    Open it in your editor:

    ```bash
    code ~/.continue/config.json
    ```
  </Step>
  <Step title="Set the provider endpoint">
    Set `apiBase` to your Takumo gateway URL and send your Takumo API key as an `Authorization: Bearer` header:

    ```json
    {
      "models": [
        {
          "title": "Claude via Takumo",
          "provider": "anthropic",
          "model": "claude-sonnet-4-5-20250929",
          "apiBase": "https://gateway.takumo.io/v1",
          "apiKey": "your-anthropic-api-key",
          "requestOptions": {
            "headers": {
              "Authorization": "Bearer your-takumo-api-key"
            }
          }
        }
      ]
    }
    ```

    Continue's Anthropic provider always sends `apiKey` as `x-api-key` and won't send a request without it, and the gateway doesn't accept a Takumo API key in `x-api-key`. So put your Anthropic API key in `apiKey` and your Takumo API key in the `Authorization` header under `requestOptions`. The gateway authenticates you with the Takumo API key and calls Anthropic with your Anthropic key.

    Self-hosted gateway users: replace the URL with your own.

    <Warning>Authenticating a self-hosted gateway with Takumo API keys is not yet available. Contact Takumo support at [support@takumo.io](mailto:support@takumo.io) to set up on-prem access.</Warning>
  </Step>
  <Step title="Check your autocomplete model">
    The gateway proxies two routes: `/v1/messages` for Anthropic and `/v1/chat/completions` for OpenAI. Mistral (including Codestral) and other providers are not supported yet, so a `tabAutocompleteModel` that uses them can't go through Takumo, and its requests are not scanned.
  </Step>
  <Step title="Test it">
    Open a file with secrets. Ask Continue a question about the code. Check the [dashboard](https://cloud.takumo.io/dashboard) for detections.
  </Step>
</Steps>

## Full config example

Here's a complete `config.json` with an Anthropic model routed through Takumo:

```json
{
  "models": [
    {
      "title": "Claude Sonnet (Takumo)",
      "provider": "anthropic",
      "model": "claude-sonnet-4-5-20250929",
      "apiBase": "https://gateway.takumo.io/v1",
      "apiKey": "your-anthropic-api-key",
      "requestOptions": {
        "headers": {
          "Authorization": "Bearer your-takumo-api-key"
        }
      }
    }
  ]
}
```

## Usage

Once configured, Continue works exactly the same as before. Chat and slash commands on these models route through the gateway transparently.

```
You: @config.ts Why is the database connection timing out?
Continue: Looking at your config, the connection pool max is set to 5...
```

The AI saw tokenized credentials. You got an answer that references your actual config. No difference in your workflow.

<Note>
  Continue's config supports multiple models. You can route some through Takumo and leave others direct. Useful if you want protection on sensitive projects but raw speed on throwaway scripts.
</Note>

## TypeScript config

If you use `config.ts` instead of `config.json`:

```typescript
// ~/.continue/config.ts
import type { ContinueConfig } from "@continuedev/config-types";

export function modifyConfig(config: ContinueConfig): ContinueConfig {
  config.models = [
    {
      title: "Claude via Takumo",
      provider: "anthropic",
      model: "claude-sonnet-4-5-20250929",
      apiBase: "https://gateway.takumo.io/v1",
      apiKey: process.env.ANTHROPIC_API_KEY,
      requestOptions: {
        headers: { Authorization: `Bearer ${process.env.TAKUMO_API_KEY}` },
      },
    },
  ];
  return config;
}
```

This lets you pull both keys from environment variables instead of hardcoding them.

## Troubleshooting

<Accordion title="Continue can't connect to the gateway">
  Check the basics:

  1. The gateway URL is correct and reachable: `curl https://gateway.takumo.io/health`
  2. Your Takumo API key is valid (check the dashboard), and it is in the `Authorization` header, not in `apiKey`
  3. The `provider` field is `anthropic`. The OpenAI-compatible route is temporarily unavailable, and the gateway does not serve other providers yet
  4. Restart VS Code after config changes
</Accordion>

<Accordion title="Autocomplete not going through Takumo">
  Autocomplete uses a separate config key (`tabAutocompleteModel`), so `apiBase` in `models` doesn't apply to it. Takumo can only proxy it if it uses an Anthropic model, with `apiBase` set to the gateway in that block too.
</Accordion>

<Accordion title="Secrets not being detected">
  Check [Supported Patterns](/patterns/supported) for the full list of what Takumo catches. If your secret format isn't covered, you can add custom patterns in your organization settings on the dashboard.
</Accordion>

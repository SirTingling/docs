# Claude Code

Claude Code reads environment variables for its API connection. Set two variables and every request goes through Takumo.

<Warning>Connecting AI tools through the Takumo gateway with an API key is not available yet, on `gateway.takumo.io` or on a self-hosted gateway. Contact Takumo support at [support@takumo.io](mailto:support@takumo.io) for early access.</Warning>

## Setup

<Steps>
  <Step title="Get your API key">
    Log into [cloud.takumo.io](https://cloud.takumo.io), go to **API Keys** and click **Create Key**. Copy the key immediately. It is shown once.
  </Step>
  <Step title="Set environment variables">
    Two variables. That's the whole setup.

    ```bash
    export ANTHROPIC_BASE_URL="https://gateway.takumo.io"
    export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"
    ```

    Claude Code sends `ANTHROPIC_AUTH_TOKEN` as `Authorization: Bearer`, which is the header the gateway checks. The gateway then calls Anthropic with Takumo's provider key, so you don't need an Anthropic key.

    <Warning>Set only `ANTHROPIC_AUTH_TOKEN`, and leave `ANTHROPIC_API_KEY` unset. Claude Code sends `ANTHROPIC_API_KEY` as `x-api-key`. On its own, the gateway rejects it with `401`. Next to `ANTHROPIC_AUTH_TOKEN`, the gateway forwards it to Anthropic as the provider key, so a Takumo API key in `ANTHROPIC_API_KEY` leaves your network and reaches Anthropic, and Anthropic still rejects the request with `401`. If you set `ANTHROPIC_API_KEY` to your Takumo API key from an earlier version of this page, run `unset ANTHROPIC_API_KEY`, remove it from your shell profile, then create a new key on the **API Keys** page and delete the old one.</Warning>
  </Step>
  <Step title="Run Claude Code">
    Use Claude Code like you normally would. Every request routes through the Takumo gateway automatically.

    ```bash
    claude "Refactor the database connection in config.ts"
    ```
  </Step>
  <Step title="Check the dashboard">
    Open the [Takumo dashboard](https://cloud.takumo.io/dashboard). You should see detections logged for any secrets in files Claude Code read.
  </Step>
</Steps>

## Add to your shell profile

Set the variables once so they persist across terminal sessions.

### Bash

```bash
# Add to ~/.bashrc or ~/.bash_profile
export ANTHROPIC_BASE_URL="https://gateway.takumo.io"
export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"
```

### Zsh

```bash
# Add to ~/.zshrc
export ANTHROPIC_BASE_URL="https://gateway.takumo.io"
export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"
```

### Fish

```fish
# Add to ~/.config/fish/config.fish
set -gx ANTHROPIC_BASE_URL "https://gateway.takumo.io"
set -gx ANTHROPIC_AUTH_TOKEN "your-takumo-api-key"
```

Reload your shell after adding:

```bash
source ~/.zshrc  # or ~/.bashrc, depending on your shell
```

## Usage

Once the variables are set, Claude Code works exactly the same. You don't change any commands or flags.

```bash
# All of these route through Takumo automatically
claude "Add retry logic to src/db.ts"
claude "Explain what config.ts does"
claude "Find the bug in auth/middleware.ts"
```

Every file Claude Code reads goes through the gateway. Secrets are tokenized on the way out, rehydrated on the way back.

<Note>
  Claude Code doesn't know Takumo is there. It sends requests to `ANTHROPIC_BASE_URL`, which happens to be your gateway. The gateway handles tokenization and rehydration transparently.
</Note>

## Self-hosted gateway

<Warning>Authenticating a self-hosted gateway with Takumo API keys is not yet available. Contact Takumo support at [support@takumo.io](mailto:support@takumo.io) to set up on-prem access.</Warning>

If you're running your own gateway, point to that instead:

```bash
export ANTHROPIC_BASE_URL="https://gateway.your-company.com"
export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"
```

Same two variables, different URL. A self-hosted gateway calls Anthropic with the provider key its operator configures. See [Add the Anthropic provider key](/deployment/onprem#add-the-anthropic-provider-key).

## Per-project configuration

If you only want Takumo on specific projects, set the variables in a `.envrc` file with [direnv](https://direnv.net):

```bash
# .envrc (in your project root)
export ANTHROPIC_BASE_URL="https://gateway.takumo.io"
export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"
```

Then `cd` into the project and the variables are set automatically. Leave the project and they're unset.

## Troubleshooting

<Accordion title="Claude Code ignoring the environment variables">
  Check that the variables are actually set. The second line prints `set` rather than the key itself, and the third prints nothing when `ANTHROPIC_API_KEY` is unset, as it should be:

  ```bash
  echo $ANTHROPIC_BASE_URL
  echo ${ANTHROPIC_AUTH_TOKEN:+set}
  echo ${ANTHROPIC_API_KEY:+set}
  ```

  If they're empty:

  1. Make sure you sourced your shell profile after adding them
  2. If using direnv, run `direnv allow` in the project directory
  3. New terminal windows should pick them up automatically
</Accordion>

<Accordion title="Authentication errors">
  The gateway authenticates you with your Takumo API key, then forwards requests to Anthropic with the gateway's provider key. If you're getting auth errors:

  1. Check that your Takumo API key is valid and active on the **API Keys** page
  2. Put the Takumo API key in `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY`, and leave `ANTHROPIC_API_KEY` unset
  3. On a self-hosted gateway, Takumo API keys are not accepted yet. See [Self-hosted gateway](#self-hosted-gateway)
</Accordion>

<Accordion title="Secrets not being detected">
  Run a scan to see what Takumo finds in a specific file:

  ```bash
  takumo-aegis scan src/config.ts
  ```

  If a secret type isn't detected, check [Supported Patterns](/patterns/supported) or add custom patterns in your organization settings.
</Accordion>

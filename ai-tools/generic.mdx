# Generic Setup

Any AI tool that lets you set a custom API endpoint works with Takumo. The pattern is always the same.

<Warning>The OpenAI-compatible route (`/v1/chat/completions`) is temporarily unavailable. Don't configure OpenAI-based tools to use the gateway yet. Anthropic tools are not affected.</Warning>

## Three steps

<Steps>
  <Step title="Find the endpoint setting">
    Look for a setting called "API base URL", "API endpoint", "Custom endpoint", or similar in your AI tool's configuration. Every tool that supports custom providers has one.
  </Step>
  <Step title="Change the URL">
    Replace the provider's default URL with your Takumo gateway URL:

    ```
    https://gateway.takumo.io/v1
    ```

    Self-hosted: use your own gateway URL instead.
  </Step>
  <Step title="Set your API key">
    For Anthropic tools, send your Takumo API key as `Authorization: Bearer`, the only header the gateway reads it from. Use the auth token or bearer token setting rather than the API key setting where the tool has both, because some tools send the API key as `x-api-key`, which the gateway rejects with `401`. On `gateway.takumo.io` the gateway calls Anthropic with Takumo's provider key.
  </Step>
</Steps>

That's it. Requests go through the gateway. Secrets get tokenized. Responses get rehydrated.

## Common provider URLs

Here's what to replace:

| Provider | Default URL | Takumo URL |
|----------|-------------|------------|
| Anthropic | `https://api.anthropic.com` | `https://gateway.takumo.io` |
| OpenAI | `https://api.openai.com` | `https://gateway.takumo.io/v1` |

The gateway picks the provider from the request path: `/v1/messages` goes to Anthropic and `/v1/chat/completions` goes to OpenAI. Anthropic SDKs add `/v1/messages` to the base URL themselves, so their base URL has no `/v1`. Other providers are not supported yet.

## Environment variable pattern

For CLI tools, the integration is usually two environment variables:

```bash
# Anthropic-based tools (leave ANTHROPIC_API_KEY unset)
export ANTHROPIC_BASE_URL="https://gateway.takumo.io"
export ANTHROPIC_AUTH_TOKEN="your-takumo-api-key"

# OpenAI-based tools (temporarily unavailable, see the warning above)
export OPENAI_BASE_URL="https://gateway.takumo.io/v1"
export OPENAI_API_KEY="your-takumo-api-key"
```

Any tool that reads these standard environment variables will route through Takumo without any code changes.

## Config file pattern

For tools with JSON or YAML configuration:

```json
{
  "apiBase": "https://gateway.takumo.io/v1",
  "model": "claude-sonnet-4-5-20250929",
  "headers": {
    "Authorization": "Bearer your-takumo-api-key"
  }
}
```

The exact field names vary by tool. Set the base URL to your gateway, and send your Takumo API key as `Authorization: Bearer` through an auth token field or a custom header. Don't put it in a field the tool sends as `x-api-key`, such as `apiKey` in Continue's Anthropic provider or `ANTHROPIC_API_KEY` in Claude Code. For a tool that always sends `x-api-key`, see [Continue.dev](/ai-tools/continue) for a setup that works.

## SDK pattern

If you're building your own integration with an AI SDK:

```typescript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://gateway.takumo.io",
  authToken: "your-takumo-api-key",
});

const response = await client.messages.create({
  model: "claude-sonnet-4-5-20250929",
  max_tokens: 1024,
  messages: [{ role: "user", content: codeWithSecrets }],
});
// Secrets in codeWithSecrets were tokenized by the gateway
// Tokens in the response were rehydrated by the gateway
```

```python
import anthropic

client = anthropic.Anthropic(
    base_url="https://gateway.takumo.io",
    auth_token="your-takumo-api-key",
)

response = client.messages.create(
    model="claude-sonnet-4-5-20250929",
    max_tokens=1024,
    messages=[{"role": "user", "content": code_with_secrets}],
)
```

Pass the key as `authToken` (`auth_token` in Python), which the SDKs send as `Authorization: Bearer`. Some SDK versions send `apiKey` as `x-api-key`, which the gateway rejects with `401`.

## If your tool doesn't support custom endpoints

Some tools don't let you change the API URL. For those, use the Takumo CLI to pre-process files before pasting or attaching them:

```bash
# Tokenize a file before pasting into any AI tool
takumo-aegis tokenize src/config.ts
```

This prints the tokenized version to stdout. Copy and paste it into your AI tool. When you get a response back, rehydrate it:

```bash
# Pipe the AI response through rehydrate
echo "AI response here" | takumo-aegis rehydrate
```

Or use the `shield` command for a full round-trip:

```bash
takumo-aegis shield src/config.ts --prompt "Add connection pooling"
```

<Note>
  If your tool doesn't support custom endpoints, use the Takumo CLI to pre-process files. Run `takumo-aegis tokenize` on your code before pasting it into any AI tool, and `takumo-aegis rehydrate` on the response to restore secrets.
</Note>

## Verifying it works

After configuring any tool, verify secrets are being caught:

1. Open a file with a known secret (database URL, API key, etc.)
2. Send it to your AI tool
3. Check the [Takumo dashboard](https://cloud.takumo.io/dashboard). You should see the request logged with detections
4. If the detection count is zero, check [Supported Patterns](/patterns/supported)

API keys authenticate your AI tools with Takumo. Each key has scopes that control what it can do.

## Creating a Key

<Steps>
  <Step title="Navigate to API Keys">
    Go to **API Keys** in the dashboard sidebar.
  </Step>
  <Step title="Click Create Key">
    Hit the **Create Key** button in the top right.
  </Step>
  <Step title="Name the key">
    Give it a descriptive name that identifies its purpose. Examples: `cursor-dev`, `ci-pipeline`, `staging-gateway`.
  </Step>
  <Step title="Select scopes">
    Choose a preset, **Full Access**, **Scans Only** or **Read Only**, or pick **Custom** and select permissions one by one. See [Permission Scopes](#permission-scopes) for what each one unlocks.
  </Step>
  <Step title="Choose when it expires">
    Pick **30 days**, **90 days**, **1 year** or **Never**. A key stops working at the moment it expires.
  </Step>
  <Step title="Copy the key">
    Copy the key immediately. It is shown exactly once. If you lose it, you'll need to create a new one.
  </Step>
</Steps>

## Key Properties

Every API key has the following properties:

| Property | Description |
|----------|-------------|
| **Name** | Human-readable label you assigned at creation |
| **Prefix** | Visible identifier (e.g., `tk_live_a1b2...`) used for recognition without exposing the full key |
| **Status** | **Active**, **Disabled** or **Expired** |
| **Scopes** | Granular permissions attached to this key. A key with no scopes shows **Full Access (all scopes)**, and a note with the date until which it can still use the gateway |
| **Expires** | When the key stops working, or never |
| **Created by** | Which team member created the key |
| **Last used** | Timestamp of the most recent API call made with this key |

## Permission Scopes

The Cloud API checks ten scopes, and the gateway checks one more. Each one unlocks the routes listed in [Key scopes](/api/authentication#key-scopes):

| Scope | What it unlocks |
|-------|-----------------|
| `scan:read` | Read scan results, violations, repositories and compliance data |
| `scan:write` | Send scan results and spend scan credits |
| `issues:read` | Read issues |
| `issues:write` | Acknowledge incidents and act on them. Needs the Security Lead, Admin or Owner role |
| `policies:read` | Read policies, rules and the extension policy |
| `policies:write` | Create, change, publish and delete rules |
| `audit:read` | Read the audit log |
| `reports:read` | List and download reports and read report schedules |
| `reports:write` | Generate reports and manage report schedules |
| `notifications:write` | Send the weekly digest notification |
| `gateway:proxy` | Send AI traffic through the Takumo gateway. Needs the Member, Security Lead, Admin or Owner role |

The presets map to these scopes:

| Preset | Scopes |
|--------|--------|
| **Full Access** | All eleven, including `gateway:proxy`. **Select all** in **Custom** picks the same set |
| **Scans Only** | `scan:read`, `scan:write` |
| **Read Only** | Every `:read` scope: `scan:read`, `issues:read`, `policies:read`, `audit:read`, `reports:read` |

### What your role can grant

A key can't do more than the person who creates it. The dialog only offers the scopes your role allows, and Takumo refuses a request for any other scope:

| Role | Scopes it can put on a key |
|------|----------------------------|
| Owner, Admin | All eleven |
| Security Lead | All except `notifications:write` |
| Member | `scan:read`, `scan:write`, `issues:read`, `policies:read`, `audit:read`, `reports:read`, `gateway:proxy` |
| Viewer | `scan:read`, `issues:read`, `policies:read`, `audit:read`, `reports:read` |
| Billing Admin | `audit:read` |

Older keys can hold `events:read`, `team:read` or `webhooks:manage`. No route uses them yet, so the dialog no longer offers them.

<Note>Metrics keys on the **Streaming** page are a different kind of key. They start with `tksk_` and only read stream metrics from the router. Use API keys, which start with `tk_live_` or `tk_test_`, for the REST API.</Note>

## Managing Keys

You can perform the following actions on existing keys:

- **Disable Key** or **Enable Key**: switch between **Active** and **Disabled**. A disabled key rejects all requests from the next request on, and can be enabled again later.
- **Delete Key**: remove the key entirely. This cannot be undone.
- **View Permissions**: inspect the full scope set attached to a key.

## Dashboard Stats

The API Keys page shows summary stats at the top:

- **Total keys**: keys that have not been deleted, active or disabled
- **Active**: keys currently in `active` status
- **API calls (24h)**: not counted yet, so it shows 0
- **Last call**: timestamp of the most recent API call from any key

## Plan Limits

| Plan | Max API Keys |
|------|--------------|
| Free | 3 |
| Pro | 10 |
| Enterprise | 20 |
| Custom | Unlimited |

Revoked and deleted keys do not count. When you hit the limit, creating a key is refused until you revoke one or upgrade. Keys you already have keep working, including after a downgrade, where an **Over your plan limit** banner names the overage.

Each key is also limited to a number of gateway requests a minute by your plan. See [Gateway limits by plan](/api/rate-limits#gateway-limits-by-plan).

<Warning>Deleting a key is permanent. Any tool using that key will immediately lose access. Disable it first if you're unsure.</Warning>

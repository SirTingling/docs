API keys authenticate your AI tools with Takumo. Each key has scopes that control what it can do.

## Creating a Key

<Steps>
  <Step title="Navigate to API Keys">
    Go to **API Keys** in the dashboard sidebar.
  </Step>
  <Step title="Click Create Key">
    Hit the **Create Key** button in the top right.
  </Step>
  <Step title="Name the key">
    Give it a descriptive name that identifies its purpose. Examples: `cursor-dev`, `ci-pipeline`, `staging-gateway`.
  </Step>
  <Step title="Select scopes">
    Choose a preset, **Full Access**, **Scans Only** or **Read Only**, or pick **Custom** and select permissions one by one. See [Permission Scopes](#permission-scopes) for what each one unlocks.
  </Step>
  <Step title="Copy the key">
    Copy the key immediately. It is shown exactly once. If you lose it, you'll need to create a new one.
  </Step>
</Steps>

## Key Properties

Every API key has the following properties:

| Property | Description |
|----------|-------------|
| **Name** | Human-readable label you assigned at creation |
| **Prefix** | Visible identifier (e.g., `tk_live_a1b2...`) used for recognition without exposing the full key |
| **Status** | `active`, `disabled`, or `revoked` |
| **Scopes** | Granular permissions attached to this key |
| **Created by** | Which team member created the key |
| **Last used** | Timestamp of the most recent API call made with this key |

## Permission Scopes

The Cloud API checks six scopes. Each one unlocks the routes listed in [Key scopes](/api/authentication#key-scopes):

| Scope | What it unlocks |
|-------|-----------------|
| `scan:read` | Read issues, violations, repositories and compliance |
| `audit:read` | Read the audit log |
| `policies:write` | Create, update, delete and publish rules |
| `reports:read` | Read reports and report schedules |
| `reports:write` | Generate reports and manage report schedules |
| `notifications:write` | Send the notification digest |

A key with no scopes passes every scope check, so it has the same API access as a key with all six. Give each key only the scopes its tool needs.

The **Custom** picker lists nine permissions. Two of them, `scan:read` and `policies:write`, are scopes the API checks today. The others (`scan:write`, `issues:read`, `issues:write`, `events:read`, `policies:read`, `team:read`, `webhooks:manage`) are stored on the key but no API route checks them yet. The presets map to these permissions:

| Preset | Permissions |
|--------|-------------|
| **Full Access** | All nine |
| **Scans Only** | `scan:read`, `scan:write` |
| **Read Only** | `scan:read`, `issues:read`, `events:read` |

<Warning>No preset and no **Custom** permission grants `audit:read`, `reports:read`, `reports:write` or `notifications:write`. A key created on this page with any permission selected gets `403` from the audit log, reports and notification digest routes.</Warning>

## Managing Keys

You can perform the following actions on existing keys:

- **Toggle status** -- Switch between `active` and `disabled`. A disabled key rejects all requests but can be re-enabled later.
- **Delete permanently** -- Remove the key entirely. Cannot be undone.
- **View permissions** -- Inspect the full scope set attached to a key.

## Dashboard Stats

The API Keys page shows summary stats at the top:

- **Total keys** -- All keys ever created (including deleted)
- **Active keys** -- Keys currently in `active` status
- **API calls (24h)** -- Total API calls across all keys in the last 24 hours
- **Last call** -- Timestamp of the most recent API call from any key

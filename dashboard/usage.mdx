The Usage page shows how your organization consumes Takumo: scans processed, credits used, API calls made, and how close you are to plan limits.

---

## Overview metrics

The top of the page shows:

| Metric | Description |
|--------|-------------|
| **Scans this period** | Total code scans (Shield + Sentinel) in the current billing cycle |
| **Credits used** | Credits consumed by scans, reviews, fix suggestions, and other operations |
| **Credits remaining** | How many credits are left in your plan |
| **API calls** | Total API requests made via API keys |

---

## Usage breakdown

The cost forecast shows **Not enough data yet** until credits have been used in the current period, because there is nothing to project from.

A chart shows daily usage over the selected period (7, 30, or 90 days). You can view by:

- **Scan type**: Shield scans, Sentinel reviews, code reviews
- **Feature**: Transforms, Brain queries, secret detection
- **API key**: Which key generated the most traffic
- **Member**: Per-user usage (for session-based scans)

---

## Plan limits

The Usage page shows credits and activity. Every plan limit, with your usage against it, is on the [Limits](/dashboard/limits) page. Takumo does not enforce limits by operation, so the per action counts here have no ceiling of their own. Credits are the one metered cap.

When you reach 80% of your included credits, a warning banner appears. Free stops at the cap. Paid plans follow the spending cap you set under [Billing](/dashboard/billing).

---

## Credit system

Credits are consumed by operations:

| Operation | Cost |
|-----------|------|
| Shield scan | 1 credit |
| Real-time scan | 1 credit |
| Policy evaluation | 1 credit |
| Sentinel review | 2 credits |
| Fix suggestion | 3 credits |
| Code review | 5 credits |

Credits reset at the start of each billing cycle. Free credits reset every month, 30 days after the organization was created or moved to Free. Unused credits don't roll over. Pro and Enterprise plans support overage at $0.02 per credit. Free plans are hard-capped. This page shows the overage for the period and how much of it is reported to billing, waiting to be reported, not billable yet or carried to the next period. See [Billing & Plans](/dashboard/billing#how-overage-is-billed).

## Rate limits

Gateway rate limits are separate from credit limits and follow your plan. See [Gateway limits by plan](/api/rate-limits#gateway-limits-by-plan).

Rate limit headers (`X-RateLimit-Remaining`, `X-RateLimit-Reset`, `Retry-After`) are included in every API response. See [Error Codes](/reference/error-codes) for details.

------|-----------------|----------------|
| Free | 30 | 500 |
| Pro | 60 | 2,500 |
| Enterprise | 120 | 5,000 |
| Custom | 500 | 20,000 |

Rate limit headers (`X-RateLimit-Remaining`, `X-RateLimit-Reset`, `Retry-After`) are included in every API response. See [Error Codes](/reference/error-codes) for details. For a full breakdown of per-operation rate limits, see [Plan Comparison](/reference/plan-comparison).

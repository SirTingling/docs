Manage your event pipeline from the dashboard. Create destinations, set up subscriptions, monitor the dead letter queue, and track delivery receipts.

<Note>Requires `streaming.read` permission to view, `streaming.write` to manage, `streaming.admin` for full control. Billing Admins have no streaming access.</Note>

## Pages

### Overview

Pipeline health at a glance:
- Active destinations count
- Active subscriptions count
- Events delivered (last 24h)
- Failed deliveries (DLQ size)

### Destinations

Where events are delivered. Five types are available:

| Type | What you configure | How Takumo sends |
|------|--------------------|------------------|
| **Splunk HEC** | HEC base URL and token | `POST /services/collector/event` with `Authorization: Splunk <token>` |
| **Datadog Logs** | Site and API key | `POST https://http-intake.logs.<site>/api/v2/logs` with `DD-API-KEY` |
| **New Relic Logs** | Region (US or EU) and license key | `POST https://log-api.newrelic.com/log/v1` (EU: `log-api.eu.newrelic.com`) with `Api-Key` |
| **Elasticsearch** | Cluster URL, index, and an API key or user name and password | `POST /_bulk` with one NDJSON line pair per event |
| **Webhook** | HTTPS URL, signing secret, optional token | `POST <url>`, signed with `X-Takumo-Signature-256`. See [Verifying streaming webhooks](/concepts/streaming#verifying-streaming-webhooks) |

Events are sent as JSON. See [Event format](/concepts/streaming#event-format) for the fields and how each destination type wraps them.

Credentials are encrypted at rest with AES-256-GCM, bound to the organization and destination, and never shown again after saving.

Destination URLs must be public HTTPS addresses. Private, loopback, link-local and other reserved addresses are refused, including when a hostname resolves to one.

An optional rate limit caps events per second for one destination. Leave it blank for no limit.

### Subscriptions

A subscription decides which events one destination receives. A destination with no enabled subscription receives nothing. Each subscription can filter by:

- minimum severity: `INFO`, `LOW`, `MEDIUM`, `HIGH` or `CRITICAL`
- categories to include or exclude: `SECRET_LEAK`, `VULNERABILITY`, `CODE_QUALITY`, `ARCH_DRIFT`, `POLICY_VIOLATION`, `PATTERN_DEVIATION`, `LICENSE_RISK`
- rule ids to include or exclude

An event goes to a destination when any of that destination's enabled subscriptions matches it. Enable or disable a subscription without deleting it.

### Dead Letter Queue

Failed deliveries land here. For each failed event:
- Failure reason and HTTP response code
- Original event payload
- Retry count
- **Retry** button for individual events
- **Bulk retry** for clearing the queue

A delivery goes to the DLQ after its retries run out, or straight away when the destination answers with an error that won't change on retry, such as a bad token (`401` or `403`) or a rejected payload (`400`). Rate limits (`429`) and timeouts (`408`) are retried, and Takumo waits for the destination's `Retry-After` when it sends one.

**Retry** sends the original event to that destination again, once, and the entry leaves the queue. If the stored event is no longer available, the entry stays in the queue so nothing is marked done that wasn't sent.

### Receipts

Every delivery attempt is tracked:
- Delivery status (success, failed, pending)
- HTTP response code
- Timestamp
- Duration
- Retry count

Download receipts as CSV from the **Receipts** tab.

### Failure notifications

When a destination keeps failing, Takumo stops sending to it for a minute and emails the organization's alert recipients. If the destination has a notification webhook, Takumo posts the same notice there. Takumo tries up to 3 times, waiting 1s then 2s, before dropping a notification.
